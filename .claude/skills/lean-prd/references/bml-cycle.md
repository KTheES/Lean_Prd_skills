# Build-Measure-Learn을 문서 생성 순서로 옮기기

이 문서는 SKILL.md가 "왜 그 순서로 섹션을 만드는지"의 근거입니다. 워크플로우를 수정하거나, 사용자가 "순서를 바꿔 달라"고 할 때 읽으세요.

## 1. BML은 거꾸로 계획한다

Eric Ries는 사이클을 Build → Measure → Learn 순서로 *실행*하지만, *계획*은 반대로 한다고 말합니다.

1. **Learn** — 무엇을 배워야 하는가? → 가장 위험한 가설이 무엇인지 정한다.
2. **Measure** — 그것을 배우려면 무엇을 측정해야 하는가? → 지표와 통과/실패 기준을 정한다.
3. **Build** — 그 측정을 가능하게 하는 최소한의 것은 무엇인가? → MVP 범위를 정한다.

따라서 PRD 생성 순서는 다음과 같습니다. 각 단계는 앞 단계의 산출물을 입력으로 받습니다.

| 단계 | 생성 파일 | 입력 | 핵심 산출 |
|---|---|---|---|
| ① 문제·가설 | 01, 02 | 사용자 아이디어, 되물음 답변 | 가설 목록 (H1…), 리스크 순위, 얼리어답터 |
| ② 지표·판단 기준 | 05 | 가설 목록 | 가설별 지표 (M1…), 목표치, Vanity 제외 |
| ③ MVP 범위 | 03, 04 | 가설 + 지표 | MVP 유형, In/Out, 사용자 스토리 |
| ④ 실험 설계 | 06 | 가설 + 지표 + MVP | 가설별 Build/Measure/Learn 계획, 임계값 |
| ⑤ 실행 자원 | 07, 08 | MVP 범위 + 실험 계획 | 팀, 기술 스택 (MVP를 만들 수 있는 최소 구성) |
| ⑥ 시간축 | 09 | 실험 계획 + 자원 | 마일스톤 = 검증 단위, 종료 조건 = 지표 목표치 |
| ⑦ 안전장치 | 10 | 가설 + 지표 + 마일스톤 | Pivot 트리거, Pivot 옵션, Kill 조건 |
| ⑧ 요약·기록 | 00, 11 | 전체 | 개요(Lean Canvas), 로그 초기화 |

00-overview를 **마지막**에 쓰는 이유: 개요는 다른 섹션의 요약이므로 먼저 쓰면 나중 섹션과 어긋납니다.

## 2. 가설의 두 종류

| 종류 | 질문 | 예 | 검증 실패 시 |
|---|---|---|---|
| **가치 가설 (Value)** | 고객이 이 제품을 실제로 가치 있게 여기는가? | "주 3회 이상 할 일을 미루는 대학생은 AI가 순서를 정해 주면 완료율이 오른다" | 솔루션/세그먼트 Pivot |
| **성장 가설 (Growth)** | 새 고객이 어떻게 이 제품을 발견하는가? | "완료 화면 공유 기능으로 사용자당 0.3명 이상이 유입된다" | 채널/엔진 Pivot |

MVP 단계에서는 가치 가설이 우선입니다. 가치가 없는 제품의 성장 가설은 검증할 의미가 없습니다.

## 3. "가장 위험한 가정" 고르기

모든 가설에 **불확실성 × 치명도**를 매깁니다 (각 1~5). 곱이 가장 큰 가설이 첫 번째 실험 대상입니다.

```
H1 문제 존재: 불확실성 2 × 치명도 5 = 10
H2 AI 추천 신뢰: 불확실성 4 × 치명도 5 = 20  ← 첫 실험
H3 유료 전환:   불확실성 5 × 치명도 3 = 15
```

이 순위가 마일스톤 순서를 결정합니다. MS0는 반드시 점수가 가장 높은 가설을 다룹니다.

## 4. 사이클 기록 규격 (11-bml-log.md)

각 사이클은 아래 7개 필드를 가집니다. 누락되면 다음 사이클에서 "왜 그 결정을 했는지" 재구성할 수 없습니다.

```
## Cycle N — <날짜> — 대상 가설: H#
- 가설(그대로 인용):
- Build: 무엇을 / 얼마나 걸렸나 / 링크
- Measure: 지표(M#) / 샘플 수 / 결과값 / 정성 피드백 3줄 요약
- 사전 임계값: 통과 ≥ X / 실패 < Y  (06-experiment-plan.md 인용)
- Learn: 결과가 임계값 대비 어디에 있는가, 예상과 다른 점
- 결정: Persevere / Pivot(<유형>) / Kill  — 근거 1문장
- 변경된 섹션: 01 §…, 03 §…, 09 MS1 종료 조건 …
```

## 5. Pivot / Persevere 판단 규칙

| 상황 | 기본 판단 |
|---|---|
| 주 지표가 통과 임계값 이상 | Persevere → 다음 가설로 |
| 주 지표가 실패 임계값 미만이고 정성 피드백도 부정적 | Pivot (유형은 10-risks-and-pivot.md의 사전 옵션에서 선택) |
| 주 지표가 두 임계값 사이 (회색 지대) | 1사이클 더 Persevere하되, 실험 설계를 바꾼다 (샘플 확대 또는 변수 축소). 2회 연속 회색 지대면 Pivot |
| 실험 자체가 실패 (샘플 부족, 측정 오류) | 결정 보류, 실험 재설계. 이것은 Persevere가 아님 |

Pivot은 "비전을 유지한 채 전략을 바꾸는 것"입니다. 비전 자체가 틀렸다고 판단되면 Kill입니다.
