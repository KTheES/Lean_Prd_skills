# PRD 검증기 확장 증빙

실행일: 2026-10-28, 2026-10-30

기본 검증기의 `CUSTOM_RULES`에 네 가지 규칙을 추가했다. 실제 제출 문서는 수정하지 않고 임시 복사본에 오류를 주입한 뒤 검증기가 실패하는지 확인했다.

## 규칙 1 — 분석 이벤트 이름 일치

- 오류 주입: `04-requirements.md`의 `waitlist_submitted`만 `waitlist_sent`로 변경
- 기대: 04와 05의 이벤트 집합 불일치 탐지
- 실제 결과:

```text
FAIL [events] 04/05 이벤트 불일치: 04에만 ['waitlist_sent'], 05에만 ['waitlist_submitted']
```

## 규칙 2 — 역할별 FTE와 담당 마일스톤

- 오류 주입: PM 역할의 FTE를 `협의`, 담당을 `전체`로 변경
- 기대: 숫자 FTE와 `MS#` 누락 탐지
- 실제 결과:

```text
FAIL [team] 숫자 FTE가 없는 역할: PM/연구자
FAIL [team] 담당 MS가 없는 역할: PM/연구자
```

## 규칙 3 — 지표 목표와 실험 통과 기준

- 오류 주입: M1 목표는 60%로 유지하고 E1 통과 임계값만 70%로 변경
- 기대: 결과를 본 뒤 성공 기준을 바꿀 수 있는 문서 불일치 탐지
- 실제 결과:

```text
FAIL [threshold] E1 M1: 05 목표 60 != 06 통과 70
```

## 규칙 4 — 실험 E# 교차 참조

- 오류 주입: E1 설계 블록의 Measure 지표를 H1과 연결되지 않은 `M2`로 변경
- 기대: E1→H1과 M2→H2 연결이 충돌하는 것을 탐지
- 실제 결과:

```text
FAIL [E#] E1: M2이 05에서 가설 H1에 연결되지 않음
```

추가로 검증기는 E# 중복·연속 순번, 우선순위 표와 설계 블록의 H# 일치, 05에 정의된 M#, 09에 정의된 MS#, 판단 기준·일정 표의 누락을 함께 검사한다.

## 정상 문서 결과

```text
결과: FAIL 0 · WARN 1 · ok 15
=> 통과
```

WARN 1은 `11-bml-log.md`의 사람 검토 메모가 아직 비어 있다는 정직한 상태 표시다. 사람 검토를 가장해 경고를 없애지 않는다.
